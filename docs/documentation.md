# 组件文档规范

Yahha UI 是一套漫画手账风 React 组件库，面向个人博客、个人主页与内容网站。文档应让使用者选对组件、复制示例、理解状态和完成接入；栏目数量与其他库一致，并不能证明内容完整。

## 品牌与文案

品牌愿景是「一起做，全宇宙最可爱的 UI 组件库」，长期标语是「把可爱，搭进你的世界」。全站保持一致的品牌名称、视觉语言和操作用语。故事用于首页品牌介绍和示例文章；导航、搜索、安装步骤、API 与错误提示直接说明任务、结果和下一步。

「Yahha 星球」是首页与示例中的场景名称，正式产品名为 `Yahha UI`，技术身份为「漫画手账风 React 组件库」。纸面、配色、角色图案和示例内容共同体现调性，技术说明使用开发者熟悉的名称。

示例作者统一称为「库米」。组件示例、组合示例与完整博客中的作者介绍、署名、表单默认值和重置值使用同一名称；显式单字头像缩写使用「米」。修改示例时同步核对展示源码、生成文档和相关测试。

示例文章用具体动作和画面写故事，围绕当前内容展开。界面文案应提供用途、操作或状态信息，信息完整后不再补一句寒暄。避免反复堆叠「可爱」「有爱」「发光」「发芽」，也不靠幼儿口吻、缩小词或感叹号制造亲切感。

组件文档说明准确的名称、能力与限制；按钮写明动作和对象，字段标签对应真实修改的内容，反馈先说明结果，再给出恢复方式。加载、错误、空状态的必要信息由可见文字、图标与语义表达，角色表情只作补充。

品牌名固定写作 `Yahha UI`，安装包与代码导入使用 `yahha-ui`，产品定位使用「漫画手账风 React 组件库」。入口使用「开始使用」「浏览组件」「体验示例网站」，代码操作使用「展开代码」「收起代码」「复制代码」「已复制」。同一组件的中文名、同一操作与状态全站一致；组件导出名、路由和章节锚点保持稳定。

普通章节标题、导航、按钮与字段标签不加句末句号，完整说明句与品牌宣言使用中文标点。中文与 React、API、数字之间留空格。品牌愿景表达共同建设的目标，发布状态、兼容性和许可范围按事实说明，不把网站上线、npm 发布与稳定版本混写。

素材来源在对应目录记录，许可范围统一引用[第三方内容说明](../THIRD_PARTY_NOTICES.md)，使用指南按需链接来源记录。

## 分类与命名

网站内容区域与组件分类分别维护。页面通过 `area` 标明主要归属：「开始使用」提供项目介绍、安装与使用定制；「组件」提供总览、公共组件 API 和主题配置；「组合示例」提供可复制的组合示例；「设计与素材」提供视觉规范和可选资源。顶栏、当前区域侧栏和相邻文档应使用同一归属。完整博客是新标签页打开的示例网站，不作为公共组件列入目录。

组件总览属于组件区。ReadingExample、BlogArchive、ArticleActions 等是组合示例，不增加公共组件计数；角色、插画与动效文件是可选资源。目录与搜索结果应让使用者分辨组件、指南、组合示例和素材，不用一套名称混指不同内容。

官网按通用、排版、布局、表单、内容展示、导航、浮层、反馈组织组件，ThemeProvider 单列主题配置。`component-catalog.ts` 是名称、中文名、描述、分组和搜索别名的唯一维护位置；侧栏、总览与页面复用它。DropdownMenu 承载操作菜单，Select 承载值选择，Tabs 切换内容面板，不能只因外观接近而混用。

Popover 的中文名称使用「弹出面板」，Alert 使用「提示条」；「浮层」继续作为组件分类名称，原组件旧称保留为搜索别名。同类最小接入示例统一使用「基础用法」，状态对照、内容主题与组合示例按实际用途命名。

分类是本库的信息架构选择，不是行业唯一标准。它不决定组件源码的文件夹归属，也不改变英文导出名和路由。旧分类链接保留结果集，相关组件链接用于跨分类选型。

## 页面内容

README、文档索引和“开始使用”先帮助使用者完成首次运行：说明当前安装来源，给出安装、样式、必需的主题设置和一个可直接运行的组件示例。复制其他组合、可选素材、离线文档与部署按需链接；构建验收、版本清单和仓库维护机制集中到[协作说明](../CONTRIBUTING.md)。

每页按用途组织说明，至少提供：

1. 用途与选型：放在代码演示之前，说明适合的任务与重要的邻近组件区别。
2. 可运行示例：基础用法在先，状态、组合和定制在后。标题、说明与代码对应；每个示例只突出一个主题。
3. API：属性、说明、类型、必填项、默认值；回调参数、原生属性、ref 和样式作用位置按实际实现解释。
4. 相关组件：提供可到达的文档链接，帮助使用者继续选择。

按组件的实际复杂度补充以下内容，不强制所有页面有相同章节：

- 排版与布局：HTML 元素、标题层级、行内组合、分隔语义、长内容与外层布局责任。
- 表单：标签、辅助说明与错误关联，受控或非受控用法，提交、重置、只读和禁用。
- 导航与浮层：键盘操作、打开关闭、焦点返回、长内容、视口边缘与 Portal。
- 图片和头像：替代文字、尺寸和比例、回退与恢复。
- 反馈：出现时机、是否播报、关闭或恢复入口、等待与内容占位的区别、减少动效。
- 主题：样式导入、公开 tokens、嵌套和 Portal 传播。

简单 Text 不需要键盘表，复杂 Select 和 Dialog 需要清楚的键盘与焦点说明。不要把 className/ref、HTML 语义、业务状态、尺寸规范和键盘全部放进一个“语义与使用约定”栏目。公共视觉规则引用设计语言，API 已解释的作用目标不反复抄写。

示例标题优先写组件能力或交互模式，例如“自定义选项内容”“条件字段与表单值”“未保存修改的关闭确认”。手记、收藏夹和阅读清单等具体内容留在演示中，操作按钮写明动作与对象。不要直接把“把手记放进收藏夹”这类业务动作当作示例标题，让读者先理解业务再猜演示重点。一句话说明交代如何观察该能力，无需罗列示例中的全部按钮和分支。

新增示例前，先核对同页已有例子是否已经覆盖受控值、校验、提交和重置。自定义选项等单一能力例只保留必要控件；确有独立价值的异步回滚、条件字段或焦点恢复流程可以保留，并用对应能力命名。已经清楚的标题不为统一措辞而强行改名，示例数量也不作为完善程度的目标。

逐组件完善时，先核对实现、公开 API、原生语义和真实使用，再决定补能力、修复行为或调整呈现。其他库已有某个参数，不代表本库也需要；文档精简、拆分演示与新增公共能力分别记录。保留库的既有画风，状态与动效也使用同一套视觉语言。

主区优先提供最小用法和直接可见的能力对照；已有禁用或加载能力时，不要求读者先完成复杂流程才能看见。字号、色调、尺寸等对照优先各自聚焦。表单、请求回滚、列表移除和焦点恢复等完整组合可放进默认折叠的进阶区，保留源码与旧深链接；不要因精简而删除错误、恢复入口或原生表单能力。正文的长词、标题的层级、容器中的内容等是对应组件的合理演示对象，不把所有组件机械压缩成空白样本。

可访问性说明优先回答如何命名、如何操作、状态如何传达以及关闭后焦点去哪里；原生按钮用简短说明即可，复杂浮层再展开键盘与焦点规则。布局或定制章节应给出公开属性的具体写法、可运行示例或明确的指南入口，避免只复述尺寸、颜色和 className/ref 的 API 行。组件之间的继承关系、内部辅助组件名和空值包装判断留在开发说明中，不作为使用者必须了解的内容。

案例分为独立的标题说明、演示画布和代码区：标题与一句目的或操作说明放在画布边框之外，源码展开、复制和完整接入放在画布下方；正文与侧栏共用同一标题和锚点。简短的按钮或浮层案例可居中展示，表单、阅读与组合案例保持原有布局。尺寸、变体和状态对照使用简短中文标签，必要时保留 sm / md / lg 等标识，每组优先只改变一个条件。完整属性写法放在源码和 API，像素尺寸集中说明，不在每个样本上重复。静态对照的范围在案例顶部说明一次，预览不再重复边界段落。示例只通过公开属性与使用方自己的布局参数接入，不依赖组件内部 CSS 变量。

演示画布只放实际组件、必要的使用内容和运行反馈。字段的可见标签、填写帮助、错误提示，以及 Text、Heading、Alert 等组件自身的文字是演示对象，应当保留；React 状态、原生字段机制、键盘规范和本例边界集中到画布外说明。反馈使用简短、身份明确的小号次要文字，普通基础案例不同时输出标签、参数与值，也不带入摘要生成等额外业务正文。一次操作更新一份结果，不能保留已经无关的旧结果；真实反馈组件自身的消息仍使用其默认层次。复杂的编辑、草稿保留和恢复流程放在组合案例中，最小用法不引入与组件接入无关的业务状态。

同一用途或选型信息集中说明一次，不在“何时使用”、示例介绍和每个样本下重复。示例介绍通常一句话点明主题，确有必要时再补操作或边界；简单变体对照只保留组件和简短类型标签，不为每个按钮附加完整用途段落。精简时保留禁用原因、错误、等待和结果等真实状态反馈；验收同时检查信息是否完整、是否重复，以及演示区是否仍以组件为重点。

示例说明只描述该示例实际展示的结果。区分组件内置行为、浏览器原生行为和调用方实现的流程；静态外观示例应明确范围，不能把演示中的等待、保存、校验、提交或回焦写成组件自动提供的能力。

只说明当前存在的能力。不能为了与其他库一致而添加 API，不能把内部 CSS 变量承诺为稳定入口，也不能把使用建议写成组件会自动完成的行为。兼容性与可访问性说明以实现和验证为依据。

## 文件与内容来源

- `playground/src/docs/components/<id>.tsx`：对应组件的说明、API 数据、原始示例引用和章节组织。
- `guides/`：按页维护指南、阅读组合、状态组合与设计规范；`guide-catalog.ts` 提供轻量元信息，`guide-pages.ts` 按页加载。`guides.tsx` 聚合完整模型供全站搜索使用，`recipe-guide.tsx` 提供场景总览。
- `component-catalog.ts`：轻量元信息，不导入示例与页面正文。
- `component-pages.ts`：显式注册按组件加载的模块，失败后允许重试。
- `page.tsx`：复用元信息并生成相关组件章节；相关关系在同文件结构化维护。
- `page-helpers.ts`：共享的原生属性、按钮属性与浮层属性说明。
- `playground/src/examples/`：可运行示例。官网预览和源码展示继续引用同一个 TSX 文件。
- `docs/components/`：从同一页面模型生成的 Markdown，包括正文、API、章节锚点和原始示例，不另写第二份。

源组件仍放在 `src/components/<family>/`，实现、CSS Modules、局部导出和行为测试共同维护；Button/IconButton 等共享组件族可以共用目录。文档组织调整不同时搬迁示例或素材，以免扩大相对路径变化。

## 修改与检查

修改组件说明、API 或示例后运行：

```sh
npm run sync:docs
npm run check:docs
```

`sync:docs` 读取实际页面模型生成 30 份组件 Markdown；`check:docs` 验证生成文件没有漂移、API 行与章节锚点没有重复、必要信息存在且示例来自真实 TSX。完整检查与 CI 同样运行此检查。

生成器不会从 TypeScript 类型自动推断运行时默认值或可访问性行为。Props、实现、测试与文档仍需一起核对。原始示例不被 Markdown 格式化器改写；真实安装包验收保留相对目录与素材后编译这些示例，防止源码 alias 掩盖接入问题。

既有 route、section id 和 example id 保持稳定。新增标题不替换旧 id；相关组件、Markdown 链接和总览筛选都应能继续导航。修改导航或渲染结构后，验证桌面与窄屏的目录、锚点焦点、代码复制和 API 横向阅读。

内容调整归属时，保留原章节和示例 ID，并让旧深链接跳转到对应新页面。站内入口与搜索使用新页面地址；相邻文档在当前区域内排列，避免连续阅读时跳往无关区域。

指南按任务选择布局：安装与设计参考使用紧凑页头，场景总览使用宽幅目录，不显示文章式页内导航。章节和示例可通过 `tocTitle` 缩短目录名称，或用 `toc: false` 省略重复条目；正文标题与锚点仍保留。设计参考先展示真实色样、文字和状态，再提供组合示例。较长组合可用 `disclosure` 折叠，旧章节与示例深链接应自动展开并移动焦点。

## 参考与取舍

本规范参考 [Ant Design Button](https://ant.design/components/button-cn/) 的用途、演示和 API，[Chakra UI](https://www.chakra-ui.com/docs/components/button) 的按功能组织示例，[Radix Text](https://www.radix-ui.com/themes/docs/components/text) 与 [Select](https://www.radix-ui.com/primitives/docs/components/select) 对静态内容和复杂交互采用不同文档深度，以及 [Animal Island UI](https://github.com/guokaigdg/animal-island-ui) 的主题连续性和可操作演示。

可访问性与定制内容另参考 [Mantine ActionIcon](https://mantine.dev/core/action-icon/#accessibility) 的命名与样式入口、[Radix Toggle](https://www.radix-ui.com/primitives/docs/components/toggle#accessibility) 的键盘说明，以及 [MUI Button](https://mui.com/material-ui/react-button/#customization) 的定制示例与限制说明；这些内容按组件需要组织，不要求每页使用同名章节。

这些项目的分类、API 与目录并不相同。本库保留单包 npm、既有设计语言和原始示例机制，不为复制大库的工程规模引入新文档框架。
